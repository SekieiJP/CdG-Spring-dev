# PRO・得点の内訳を別々に学習する比較

2026-10-04。84ed847から `codex/pro-component-value-research` を分けた。リセマラなし平均12.5点の方略完成が目標。現在進行中の入塾比重、成長・削除、V5の比較が使う11ファイル・設定・既存モデルは変更しない。

## 別のアプローチを試す理由

一括の最終得点予測は、新V5の同じ検証250開始で旧V1より平均絶対誤差が小さくなった。実ゲーム改善はまだ比較中。一方、[得点分布の診断](CdG-PRO-Score-Distribution.md)と[成長・削除の比較](CdG-PRO-Growth-Research.md)では、低得点の救済だけでは足りず、13点以上の回を失わずに増やす必要がある。

今回は、本体が実ゲームの終了時に計算して記録した4成分を別々に予測する。「動員点」「入退差点」「満足点」「退塾の加減点」を学習し、予測値の合計で判断する。成長の上積みと、満足・経理が足りない場合の減点を捉えやすくなるかを試す。合計を予測する目的は従来と同じで、成分に好みの重みを付けない。

## 固定する学習条件

現在のV1・取得/配置2ターン先読み・aggressive削除という同じ設定の全1,250開始/30,522公開局面を学習、別250開始/6,117局面を誤差検証に使う。V5と同じ材料で、好成績の回だけを選ばない。複数の研究実装版から集めた材料であり、固定版の独立1,250開始による到達確認とは呼ばない。

[固定ソース](../solver/research-scenarios/pro-value-v6-component-sources.json)、[全開始・版・検証分離の監査](../solver/research-results/pro-mean125-20261004/value-v6-component-source-audit.json)。Nodeは公式記録の内訳をコピーするだけで、点数の再計算やゲーム操作をしない。学習用の内訳は公開状態の入力へ混ぜない。関連6テストが通過した。

| 評価モデル | 教師 | 深さ | 木の本数 |
| --- | --- | ---: | ---: |
| scalar3x4 | 最終得点を一括で学習 | 3 | 640 |
| component3 | 公式4成分を別々に学習して合計 | 各3 | 各160、合計640 |

木を増やした効果だけと混同しないため、木の総数をそろえた一括モデルを対照にする。両方とも同じ特徴・ゲーム単位の重み・学習率0.07・16分割・行/特徴抽出率・最少葉サイズ・正則化・固定乱数の既存方式を使う。V1とV5深さ3/4も同じ誤差検証群の参照として残す。誤差検証の結果を見て本数や重みを変えない。

特徴計算・学習・モデルの合成・誤差計算はブラウザ内。4成分の教師が実得点に一致することを検査し、合成した固定木の予測が4モデルの合計と一致することを全検証局面で確認する。予測成分は切り詰めずに合計し、既存の固定木評価器で使える形にする。実ゲームの得点計算は本体の公式処理を使い続ける。

## その後の全ゲーム比較

[新しい3条件](../solver/research-scenarios/pro-mean125-component-value6-configs.json)を結果を見る前に固定した。baselineは旧V1、scalar3x4とcomponent3は上記の新モデルで、それ以外の取得・配置・削除・リフレッシュ条件をそろえる。同じ新しい250開始を各条件で全採用し、学習・誤差検証の開始群と分ける。初期・途中のリセット、結果による除外、実シードや未来の順序の判断への受け渡しをしない。

研究用ブラウザは合計3つ以内とする。成長・削除の最後のhorizon3-delete-rolloutが完走して空いた1枠で学習を開始し、各新モデルの実ゲーム接続確認の後、1ブラウザで3条件を順に実行する。待ち時間だけを理由に進行中のゲームを打ち切り・再開しない。

平均と名目95%区間、中央値、下位10%、13点/S+/15点の到達、8点未満、退塾、対応する得点帯の移動を確認する。予測誤差が下がっただけで採用しない。有望な版を固定後、調整に使わない独立1,000開始以上で平均12.5点を確認し、その同じ版で全51カードの場面別評価をまとめる。成分ごとの予測差をカードの因果パワーとは扱わない。
