## MASTER側への取り込み手順

MASTER側の現在の作業を保存したうえで、その専用チェックアウトから実行する。

```sh
git merge codex/shared-improvements
```

難易度は`game/js/difficultyExtensions.js`から固有モジュールを読み込み、`registerDifficulty`で登録する。新たな配置先・持続カード・所在・固有状態の保存には[共通API](CdG-Common-API.md)を使う。

競合を確認する箇所は`main.js`、`difficultyConfig.js`、`gameState.js`、`uiController.js`、版を含む相対import。登録・保存・結果表示を共通処理へ接続し、MASTERのカードデータと固有処理を専用モジュールへ置く。FRESH・PROの共通化でCSV値は変更していない。

版は`node scripts/set-build-version.mjs vYYYYMMDD-NNNN`でまとめて更新する。相対importの版が混ざると、別URLのモジュールとして設定の登録先が分かれる。新しいモジュールを追加した後も参照を揃える。保存互換性はユーザーの決定どおり上8桁で判定する。

現在の自動プレイ戦略・目標値はFRESH／PRO向け。MASTERのターン全体のフック・独自得点・新取得方法を加える場合は、その難易度の予測と戦略を検証する。狙った構築の完成率約70%やPRO比0〜35%の出力増は、MASTER側で成立条件を決めた後の評価対象である。
