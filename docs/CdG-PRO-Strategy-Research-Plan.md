# PRO攻略分析計画

2026-10-03。取得推薦の改善に先立ち、人がプレイするときに使える攻略方針を探す。推薦本体の重み・UI・カード・ルールはこの分析で変更しない。作業ブランチは `codex/pro-strategy-research`、起点は `codex/pro-acquisition-assist` の `0589367`。MASTER開発と独立して進める。

## 評価する目的

1. 一発勝負：**最初に提示された候補から、リセマラ・ゲームのリセットなしで1ゲームを完走する**。実際の最終得点の中央値を優先する。同点なら下位10%、8点未満の割合、平均点も確認する。開始準備としての候補厳選も含めない。
2. 15点狙いの繰り返し挑戦：**初期リセマラを使えるのはこのカテゴリだけ**。実際の最終得点15点以上の割合を優先し、S+の14点と区別する。失敗時の得点分布、成功までの完走数、リセット数と所要時間を併記する。

ゲーム内の回数制限付き研修リフレッシュは通常ルールの操作として両カテゴリで利用できる。リセマラ後の中央値・下位分位は15点狙いの補助指標で、一発勝負の成績改善として扱わない。

得点はブラウザの本体 `ScoreManager` の結果を使う。経理・満足の15未満による退塾、入塾が体験を超えないこと、コストと条件の判定順、スタッフの解決順を共通エンジンで適用する。方略は公開済みの数値、所有カード、見えている手札・候補・提示履歴だけを見る。未来の山札順・抽選結果・乱数状態は見ない。

## 事前の仮説と比較

| 対象 | 仮説 | 他の判断を固定した比較 |
| --- | --- | --- |
| 取得 | 不足を補う方が一発勝負に向く | 現在のS+取得評価と、経理・満足を厚くする評価 |
| 取得 | 15点経路を意識すると上振れが増える | 現在の評価と、15点の複合目標への近さを加えた評価 |
| 取得 | 情熱・発想・並行カードを早く集めると天井が上がる | エンジンを重くする評価。膨張による希釈も記録 |
| 配置 | 将来の不足と次ターンのドローを考える方がよい | 現在の配置、その場の数値、中央値向け、15点向け、エンジン向け |
| 削除 | 基本カードを一律に消すと回復・入塾役を失う | 基本カードのみ積極削除、改善時のみ削除、役割を残す積極削除、削除なし |
| 組み合わせ | 各操作の改善は組み合わせても保たれる | 中央値向け、15点向け、エンジン向けの全操作を組み合わせる |

リフレッシュは全比較で同じ公開情報のS+評価を使い、取得・配置・削除の差に混ぜない。配置の探索は今見えている手札の合法な並べ方だけを比較する。将来成長は既知のデッキから固定回数の算術投影で近似する。この近似値は成功確率ではない。

## 試行数・再現性

- 傾向を比較する各方略・各場面は **最低250個の異なるシード**。動作確認の少数試行は攻略の根拠から除外する。
- 開発用は15方略×同じ250シード。ここで選んだ方略を別の検証用シードで比較する。15点はまれなので、最終候補の確認は合計1000シードを基本とする。
- 以前の100・200・60シードの結果は仮説の材料のみ。既存1000シードの結果を使う場合は別の実験として扱う。
- 同一シードの対比較、15点到達率のWilson 95%区間、中央値・平均点・到達率差の対ブートストラップを報告する。小さな差や成功0件を優劣・不可能の証明にしない。
- 本体・分析方略・カード・ランク表のハッシュ、実行設定、シード、選択・解決・削除を保存する。個別のカード保有と成功の共起は因果効果と区別する。
- 250ゲームずつ出力し、大きなイベント記録を一括でメモリに載せない。集計ツールは250未満、同じシードの重複、異なる本体・カード・得点表の混在を拒否する。

## 追加検証：初期2枚のリセマラ

ユーザーの追加方針により、**15点狙いのカテゴリでのみ**、初回研修の候補だけを見てゲームをリセットする攻略を検証する。通常の開始は新しいrunIdで乱数を作り直す。初回はR12種から**異なる4種**を提示し、2枚を選ぶ。同じカード2枚の初期取得はできない。

- 取得・配置・削除をエンジン重視に固定し、初期ペア12条件、リセットなし・初期リフレッシュあり／なしを各250完走シードで比較する。
- 特定の2種を要求すると提示確率は45/495＝1/11。受け入れたゲームの成績だけでなく、破棄した開始も全て記録する。
- リセマラ条件は公開された初回4枚だけで判定する。条件不成立ならプレイ開始前にリセット。条件成立後は通常の8ターンを最後まで行う。途中の好都合な結果を見て採用し直すことはしない。
- リセマラを使う条件ではゲーム内リフレッシュを初回に使わない。以後は同じ公開情報によるS+のリフレッシュ判断を使う。ゲーム内の消費とゲーム全体のリセットを区別する。
- 有望な厳選ペアと、条件を緩めた複数ペアの受け入れを別の1000シードで検証する。探索で最高だった観測値をそのままおすすめにしない。
- 完走回数を減らす方針と、リセット時間まで含めた効率を区別する。端末・人による操作時間は未測定なので、リセット時間／完走時間の比を変えた感度分析を行う。
- 初期条件を揃えた追加の取得・配置・削除比較は別の各250シード以上。実行は引き続きブラウザの本体ロジック、記録・統計のみ起動ツール側で行う。
