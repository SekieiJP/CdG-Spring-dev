# FRESH取得アシスト：分析記録

## 実験条件と選定

カード版 `62f21ff2…`、ランク版 `6489ecc6…`、ルール版 `20260815`。全て通常FRESH、8ターン。本体のカード値・得点・ランク条件は変更していない。取得を差し替える比較では、配置／削除を `fresh_stable` に固定した。既存方略と数式版の初回提示が全200seedで一致すること、カード／ランク／ルール版の一致を確認した。

開発・検証・最終評価はseedプレフィックスを分ける。同seedの対応を保つ2,000回のブートストラップで差の95%区間を測る。区間が0を含むことは同等性の証明ではない。選定では事前合意した「S率差を明確に判断できない場合は中央値を優先する」という手順を使う。

## 調整で重視した判断

1. 満足と経理を合計するだけでは、片方の過剰で他方の不足を隠してしまう。それぞれの不足と退塾を評価する。入塾の体験上限も別に扱う。
2. 強い効果でも、今のコストを払えない最終ターンには役に立たない。条件の将来成立は近似し、コストの可否は本体と共通の効果計算で確認する。
3. 高い単発効果だけでなく、残りターン／デッキ枚数に対する使用機会と既存デッキの希釈を評価する。初回は2枚の組み合わせで補完を見る。
4. 安全性だけを上げるsafetyは開発比較で伸びず、入塾・体験とS到達後の精度を重視するreachが有望だった。
5. S条件の補完特徴を外すと開発でS率92→91%、中央値8.8→8.9。単独の特徴が改善を説明するとまでは判断できないため、検証済みの全特徴モデルを保つ。

## 同じ公開場面からの別取得

開発seed `fresh-assist-v1-dev:0` のターン番号2（第3ターン）を使用。体験4／入塾3／満足6／経理5。候補はNo48「赤字覚悟！？ 大抽選会」、No50「事務リーダー1日派遣」、No44「今だけ！体験生特典」。数式の推薦はNo50。

公開状態を復元し、新しい同一30seedで各候補を強制取得して最後までブラウザでプレイした。

| 取得 | S以上 | 中央値 |
|---|---:|---:|
| No48 | 66.7% | 8.2 |
| No50 | 86.7% | 8.5 |
| No44 | 63.3% | 8.8 |

この場面では最大の単発効果／中央値より、経理の補完を選ぶ推薦がS率を高める方向と一致した。30試行の条件付き例であり、全場面の最適性の証明ではない。未公開の元の山札順を再現した実験ではない。

## 採用した数式と限界

重み：体験2.8、入塾3.5、満足1.9、経理2.1、S条件補完6、成立後精度3、発動・コストリスク0.8。将来条件の補間係数0.8、専任配置の可用係数0.82、配置機会係数0.75。パラメータの不足解消を重視し、条件到達後の増分を0.12倍にする。重み・全計算は `game/js/freshAcquisitionAdvisor.js` にまとめた。

残りターンの予測は、今の所有カードを使った近似であり、将来取得するカード、実際のシャッフル順、配置競合の全組み合わせを厳密には計算しない。PRO／MASTER・イベント・計算機への一般化は検証していない。FRESHのカード効果を対象とし、新難易度の特殊な置き場やトークン効果までこの数式で評価できるとは扱わない。

実プレイヤーの得点率は配置・削除の判断にも依存する。分析のS率は自動プレイ方略による測定であり、アシストを表示するだけで全プレイヤーがこの率になるという意味ではない。
