# FRESH取得アシスト：実装・分析計画

## 合意した方針

目的は、取得カードの判断を改善し、通常FRESHのS以上到達率を第一に、スコア中央値を第二に高めること。改善専用の `codex/fresh-acquisition-assist` ブランチで実装する。MASTER制作とは独立させ、ゲームルール・カード数値・配置／削除方略の変更を混ぜない。

ゲーム本体では、事前に調整した重みを持つ数式だけを計算する。その場での繰り返しシミュレーションは実装しない。精度不足が確認された場合の3秒以内のシミュレーションは、別途判断する次段階とする。

分析時の仮説・重みの選択はChatGPTが行い、ゲームの取得・配置・削除・結果計算はブラウザ上の実際のゲームロジックで行う。推薦が受け取る情報は、現在のパラメータ、トークン、所有カード、残りターン、提示候補、過去に公開された提示履歴に限定する。seed、RNG状態、未公開の山札順や候補プール順を渡さない。

## ゲーム内の表示仕様

- 設定画面の「取得アシスト（FRESH）」でオン／オフを選べる。初期値はオン。設定は保存し、変更は即時反映する。
- 通常FRESHの初回研修4枚から2枚、通常研修3枚から1枚、発想の取得／辞退が対象。PRO・MASTER・イベント・計算機は対象外。
- 候補が表示されてから5秒後、おすすめカードの背後に薄い静止した光を表示する。初回は最良の2枚組を表示し、選択中もその組み合わせを維持する。発想の辞退を推奨する場合は辞退候補を強調する。
- 自動取得・自動確定はしない。カードの寸法・タップ領域は変えず、選択済みの枠と推薦の光を区別する。説明は長押しの詳細表示に加える。
- 新候補・再読み込み・中断復帰で5秒を数え直す。選択／解除では数え直さない。オフ・確定・画面移動で待機を解除する。表示から5秒経過後にオンへ戻すと即時表示する。
- 推薦計算はp95で100ms未満、最大500ms未満を目安とする。実機iPhone 12 Safariの検証は、Chromiumの画面サイズ／タッチ設定による検証とは区別して報告する。

## 数式の評価項目

各カードについて合法なスタッフへの配置を評価し、条件・コスト・残りターン・デッキ枚数から期待使用回数とパラメータ増分を見積もる。初回は全6組を比較する。

体験、入塾、満足、経理の不足を別々に扱い、入塾の体験上限と満足／経理それぞれの退塾を反映する。S条件の成立見込み、成立後の精度による得点、コスト不足や条件未達のリスクを重み付けする。満足と経理の合計だけで安全性を判断しない。予測値は確率の実測値ではなく、推薦用の近似である。

## 分析と検証の手順

1. 既存4方略を同じ100seedで比較し、取得以外の配置・削除方略を固定する。
2. 開発用200seedで4つの重み候補を比較する。特徴を外す比較と、特定状況からの別取得の再試行で弱点を調べる。
3. 検証用500seedで有望な重みと既存方略を比較する。S率が同程度なら中央値を優先する。
4. 採用する重みを固定し、それまで使用しない1,000seedで最終比較する。最終比較を見てから重みを調整しない。
5. 配置・削除方略を変えた感度確認を行い、特定方略への依存を記載する。
6. 同seedの対応を維持したブートストラップ95%区間、S率、中央値、p10を記録する。カード・ランク・ルール版、モデル、コード識別情報、seed群を残す。

取得ごとに既知状態、候補、各選択肢の特徴・寄与・評価値、推薦、実際の選択を記録する。HTMLでカード・ターン・不足状況別に確認し、状況JSONを取り出して再試行できるようにする。カードの同伴得点・S率は相関であり、単独の因果効果とは扱わない。生ログ・HTML・CSVはローカルの除外対象へ保存する。

## 完了条件

数式による推薦、設定・5秒後表示、場面別の分析／再試行ツール、記録集計、重みの選定根拠を揃える。ユニット／ブラウザテストと画面検証を行う。未確認の実機性能・未対応難易度、モデルの近似の限界を明記する。実験結果は分析記録に追記する。
