## 決定した動作

| 要求 | 実装 |
|---|---|
| 演出の1枚送り | 演出中だけdocumentのclickを捕捉し、背景・数値・ヘッダーを含む画面全体で現在の1枚を送る。次のカード／塾アイテムは通常速度に戻す。Enter／Spaceも同じ動作。終了時にリスナーを解除する |
| 全スキップ廃止 | ボタン、説明文、全体省略の時計APIを除去。通常の演出時間は維持する |
| 取得アシストの色 | 5秒後の候補提示は維持し、黄色の光と1pxの黄色い実線に変更。通常の選択状態と別に描く |
| 手札の左右配置 | カード内を左右半分ずつに分け、左は名前→カテゴリ／レアリティ→効果、右はサムネイルのみ。画像非表示・読込失敗時は文字列を全幅にする |
| 詳細の目印 | `ⓘ 長押し`を`ⓘ`へ変更。短縮で省いた本文、実際の文字切れ、トークンの用語解説、アシスト評価があるときだけ表示する |
| PWA上端 | ステータスバー表示を`black-translucent`から`black`に変更。CSSのsafe-area値を本文の余白と固定ヘッダー内の余白へ適用し、独立画面では追加4pxを確保。上端を背景で覆い、スクロールした文字が島の背後へ透けないようにする |

目印は`ResizeObserver`・次の描画フレーム・フォント読込み後に更新する。文字切れは名前と効果文の`scrollWidth/Height`と表示寸法を比較する。全文が収まり、追加情報もなければ目印は隠す。全文でもトークン用語解説・アシスト評価が詳細側だけにある場合は表示する。目印をタップした場合も詳細を開き、通常の配置とは区別する。

PWAの余白はDynamic Island搭載機を機種名で判別せず、`env(safe-area-inset-top)`を使う。上端値が0の機種・横向きではその値に従う。ステータスバーの背後へ描画する設定については[Appleのメタタグ仕様](https://developer.apple.com/library/archive/documentation/AppleApplications/Reference/SafariHTMLRef/Articles/MetaTags.html)、safe-areaの扱いは[WebKitの説明](https://webkit.org/blog/7929/designing-websites-for-iphone-x/)を参照した。

## 非推奨カードにも取得アシスト理由が表示される理由

元の実装は、全候補を比較した評価一覧から、そのカードを含む最上位の選択肢を取り出して理由を表示していた。初回研修は2枚を選ぶため、理由はカード単体ではなく、そのカードを含む組み合わせの評価である。推奨しないカードにも評価理由があるのは比較用であり、全候補を推奨する意味ではない。

この比較情報を残し、詳細では「取得アシスト（推奨理由）」と「取得アシスト（比較評価）」を分ける。2枚選択では「このカードを含む組み合わせ」と明記する。推薦の計算方法・順位・対象難易度は変更していない。

## 保存・送信するターン履歴

`GameState.turnHistory`に取得・配置・取消・削除を順番に追加する。各記録は0始まりのターン、フェーズ、操作種別、カードNo／名前／個体ID、配置先を持つ。開始時の基本カードもターン0のstartとして記録される。同名カードを個体IDで区別する。

- 中断データに保存し、復元する。旧保存に履歴欄がない場合は既存評価ログの該当操作を引き継ぐ。旧データに残っていない操作は復元できない。
- 評価用ログの3000件上限とは別管理にし、評価ログが上限でも必要な操作履歴を落とさない。
- 計算機の配置変更も取消と配置を記録する。入力失敗で配置を戻す際は、操作履歴と評価ログも同じ時点まで戻す。
- 終了時のペイロードにコピーし、送信待ち・再読み込み・次のゲーム開始でも内容を変更しない。直近5ゲームの待機上限は従来どおり。
- 候補全体の数式評価、seedを含む詳細な評価ログは今回の送信対象にしない。

## GASの保存と反映順

受信側は`turnHistory`を検証し、「ターン履歴」シートへ保存する。24,000文字以内になるようイベント単位でJSONを分け、履歴ID・結果ID・分割Noとともに記録する。JSONを途中で切らないため、日本語・絵文字も壊さない。

スコアと履歴の書込みは同じScriptLock内で行い、flush後に受領済みにする。結果IDと分割Noで重複排除し、途中で失敗した場合も再送で不足分を補う。技術上限は10,000操作・ペイロード2,000,000文字。超過時はエラーを返し、黙って履歴を切り捨てない。

新しいGASは`turnHistoryStored: true`を返す。旧GASが成功を返してもこの項目がなければ、スコアのみ受領済みとして履歴を端末の待機キューに保持する。旧GASの32,000文字上限を超えた場合は、同じ結果IDでスコアを先に送り、履歴を保持する。GAS更新後の再送は既存のスコア行を複製せず、履歴を追記する。

0057の公開時はPagesを先に反映し、`gas/scoreReceiver.gs`の既存URLへの再デプロイは後日行う。履歴の送信待ち上限は直近5ゲーム。上限から外れた結果はスコア履歴に残るが、ターン履歴の再送対象からは外れる。
