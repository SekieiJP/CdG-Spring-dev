# リプレイ視聴・お手本プレイ：前提確認

確認日：2026-11-09

対象：`a2f9f49e28594c00312f30cd65f401274006434c`、公開ビルド`v20261107-0064`

## 結論と作業状態

ユーザーが示した「リフレッシュの候補は、次に同じレアリティから引くターンの候補に等しい」という前提は、現在の実装と一致しない。

「前提が現在の仕様と異なる場合はgoal作業を中断して知らせる」という指示に従い、新機能の実装・公開へ進まず、前提をどう扱うかの判断を待つ。

## 現在の実装

- 同じ難易度・カードデータ・シードなら、初期研修デッキは同じになる。
- 研修デッキ本体のシャッフルは初期化時と、そのレアリティの残りが空になった後の再構成時に行う。
- 候補を出すたびに、残っているカード名の一覧を別途シャッフルし、その一覧から候補を選ぶ。研修デッキの固定順に沿って引く方式ではない。
- 候補抽選の乱数系列にはターン番号・研修種別・レアリティが含まれる。リフレッシュは現在ターンの系列を続けて使い、次に同じレアリティを引くターンでは別の系列を使う。
- 候補の提示履歴と追加抽選の回数が同じなら、取得するカードを変えるだけでは、その後の候補抽選に使う残りプールは変わらない。発想研修などで追加の抽選が生じるケースまで、取得後の候補が常に同じになるという保証ではない。

根拠は`game/js/cardManager.js`の`initTrainingPool`、`shuffleTrainingDeck`、`drawTrainingCards`、`refreshTrainingCards`と、`game/js/randomSource.js`の名前付き乱数系列。

## 実行確認

製品の`GameState`と`CardManager`に、製品のFRESH / PROのCSVを読み込んで確認した。シードは`training-seed-audit-20261109`。

FRESHとPROの両方で、同一シードの初期研修デッキが一致した。初回の4候補から異なる2枚ずつを取得した後も、同じ抽選履歴での2ターン目のSR候補が一致した。

一方、PROで2ターン目のSR候補をリフレッシュした場合と、リフレッシュせず次の通常SR研修である6ターン目を迎えた場合では、次の違いがあった。発想研修を挟まない条件で、間のSSR・R研修の抽選も実行した。

| 条件 | 候補のカード番号 |
|---|---|
| 2ターン目のSRリフレッシュ | 31・29・39 |
| リフレッシュしない場合の6ターン目のSR | 38・26・31 |

比較するSRの残りデッキは抽選直前に同一で、残り45枚だった。一巡後の再構成による差ではなく、抽選に使う乱数系列の違いである。

## 再開のために必要な判断

提示された前提へ合わせる場合は、研修候補の抽選を、レアリティごとの固定した順番から取り出す方式へ変更する必要がある。既存シードの候補とCPUのプレイ結果も変わるため、現在の抽選を維持するか、前提へ合わせて変更するかを確認する。

## 再開後も維持する依頼範囲

- CPU対戦で同一シードのチェックボックスを追加し、初期値をオンにする。CPUとの同一シード対戦は毎回シードが変わるためハイスコアを記録し、同一シードのリプレイ対戦は従来どおり除外する。
- 教室防犯カメラで各ターンの取得・配置・削除を閲覧する。カード操作はできず、⏪ / ⏩で移動する。配置場面の上部ステータスは効果解決後の値を示す。同じ場面でCPUが選ぶ札に🐤を付け、CPUアイコンから理由を確認できる。UIを3案提示する。
- お手本プレイでは、入力リプレイと同じシードでCPUをプレイさせ、そのCPUリプレイを出力する。ワンボタンで防犯カメラへ移動し、取得・配置・削除を確認する。
- 公開先は開発サイト。ビルド番号は未指定のため独自に進めない。

## 調査後の決定

ユーザー回答により、前提に合わせて固定順の抽選へ変更して開発を再開する。互換性を失う更新のため、予定ビルドは`v20261110-0065`とする。上8桁が異なる0064以前の中断データ・リプレイは引き継がない。

通常研修と発想研修は同じSRデッキを共有する。発想研修で追加の候補を引けば、その分だけSRの順序が先へ進む。

お手本プレイは元リプレイのイベントを引き継ぐ。計算機は入力UIの違いとして扱い、CPUは通常の入力・選択でプレイする。

CPUとの同一シード設定は対戦ロビーのCPU側へ置き、初期値をオンにする。対戦ごとに新しいシードを作り、同一シードでもハイスコアを記録し、スコアを送信する。

本節以降の要件・実装状況は[リプレイ視聴・お手本プレイの設計](CdG-Replay-Viewing-Design.md)へ記録する。
