# 教室防犯カメラ・お手本プレイ：要件と実装計画

予定ビルド：`v20261110-0065`

公開先：`CdG-Spring-dev`の`game/`。本番リポジトリへの公開は今回の依頼範囲に含めない。

## 研修候補の順序

同じ難易度・カードデータ・シードから、同じレアリティ別の研修デッキを生成する。初期化時と、そのレアリティの全個体を提示し終えた後だけシャッフルする。候補の提示時には再抽選せず、デッキの先頭から取り出す。

同じ提示内で同名カードが重なるときは、その個体をデッキ内に残し、次の異なる名前を取り出す。残りに未提示の個体がある間は、候補枚数を埋めるためだけに再シャッフルしない。

同じ候補提示履歴なら、取得したカードを変えても次回の候補順は変わらない。通常研修と発想研修は同じSRデッキを共有するため、追加の候補提示やリフレッシュを行った分だけ順序が先へ進む。リフレッシュは次回の同レアリティ候補を先に取り出し、現在の候補は現行ルールどおり以後の循環から除く。

## CPUとの同一シード対戦

- CPU対戦ロビーにチェックボックスを置く。初期値はオン。
- 対戦のたびにCPU用の新しいシードを作り、オンならプレイヤーもそのシードを使う。
- CPUとの同一シードはハイスコア記録・スコア送信の対象とする。
- リプレイとの同一シードだけ、従来どおりハイスコアの対象外とする。履歴・スコア送信は受け付ける。
- 再戦でも新しいCPUプレイとシードを生成する。チェック状態は再戦設定へ引き継ぐ。

## 教室防犯カメラ

- リプレイを読み込み、ターンごとの取得・配置・削除の場面を閲覧する。
- カードの取得・移動・削除は操作できない。⏪ / ⏩で場面を戻したり進めたりする。
- 配置場面では、実際に配置したカードと、効果解決後のステータスを表示する。
- 各場面の実際の状態・候補・所有札を使い、既存CPU方略が同じ場面で選ぶカードへ🐤を表示する。別の通しプレイの選択を流用しない。
- 配置ではCPUが使うカードへ🐤を付ける。CPUアイコンから選択理由を確認できる。
- スマートフォン向けに3つのUI案を示し、配置と時間移動の方式を比較できるようにする。

## お手本プレイ

- 入力リプレイと同じ難易度・シードでCPUをプレイさせ、CPU自身のリプレイを出力する。
- 元リプレイのイベントを引き継ぐ。計算機の入力UIは引き継がず、CPUの選択で進める。
- 生成後はワンボタンで防犯カメラへ移動し、取得・配置・削除を確認できる。
- 通常の対戦CPUと同じ固定方略を使う。別の軽量アシストへ置き換えない。

## 保存・互換性

上8桁が変わるため、0064以前の中断データ・リプレイとの互換性は維持しない。形式名は`CDGR1.`を維持する。新しいリプレイは視聴に必要な取得候補・選択・削除前の状態を持ち、短縮後も保持する。

ゲーム中の中断保存と独立した閲覧状態を使い、視聴やCPU生成で進行中のゲームを上書きしない。閲覧・お手本生成はプレイヤーのハイスコア記録や実スコア送信を発生させない。

## 検証と現在の進捗

固定順・重複・一巡境界・リフレッシュ・発想研修の共有、CPU同一シードのハイスコアと送信を重点的に確認する。CPU方略そのものは保持し、抽選規則の変更で変わる基準プレイを区別する。

固定順の抽選とCPU同一シードの設定・ハイスコア判定を実装した。`node scripts/set-build-version.mjs v20261110-0065`で版と参照をそろえた。

単体全294件が成功。CPU同一シードの初期候補一致、オフ設定、完走と送信、再戦での新しいシードを、関連ブラウザ9件で確認した。ローカルのデスクトップ・iPhone 12寸法・Android寸法はすべてChromium。WebKitを含む公開前CIは全機能の実装後に行う。

固定PRO方略の基準3プレイは、新しい研修順で13・11・14点となった。方略モジュール・モデルのハッシュは変更せず、変更した抽選規則に合わせて基準の取得・配置解決・削除と最終結果を記録し直した。旧基準はGit履歴に残る。3件の結果から平均的な強さの向上を判断しない。

### 視聴UIの3案

| 案 | 構成 | 比較する点 |
|---|---|---|
| いつもの画面 | 既存のカード画面に近い構成。上部にステータス、中央に記録の配置・候補、下部に時間移動と選択理由 | 普段のプレイとの対応が分かりやすい |
| 記録をたどる | 左にターン・取得・配置・削除の記録、右に選んだ場面の内容 | 記録の順序を追いやすい。狭い画面ではカード領域が小さくなる |
| 並べて比較 | 記録の選択と、同じ場面でのCPUの選択を2列で表示 | 選択の違いを見比べやすい。同じカードを両列へ表示する場合がある |

操作できる表示例を3案作成した。各案で⏪ / ⏩と🐤の選択理由の開閉を試せる。カード自体は操作しない。実装に採用する案は回答待ち。

視聴用データ、場面ごとのCPU判定、イベントを引き継ぐお手本生成、開発サイトへの公開と公開後確認は未完了。UIの回答待ちの間も、これらの独立した作業を進める。
