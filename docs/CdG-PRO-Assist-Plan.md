# PRO取得推薦・分析計画

## 合意と範囲

FRESHの取得推薦は2026-10-03に公開ブランチ`main`へマージし、GitHub Pagesへの配信を確認した（v20260815-0054）。PROは同じ公開コミットから作成した`codex/pro-acquisition-assist`で開発する。MASTER開発のブランチ・カード・ルールを変更しない。

PROの主指標は **S+以上（SSを含む）の到達率**、副指標は得点中央値。実際のScoreManagerとrankPro.csvの結果で判定する。推薦表示はFRESHと共通の設定（既定オン）、候補提示5秒後の淡い背景強調、長押し詳細、初回2枚・通常1枚・発想の辞退を維持する。

ゲーム内推薦は公開済み情報と固定係数による数式のみ。乱数、未来の抽選、山札順序を参照せず、その場で将来ゲームを反復しない。分析のゲーム操作・方略評価はブラウザの実エンジンで実行する。Nodeは起動、記録、集計に使う。自動プレイからスコア送信先へ通信しない。

## 分析順序

1. 現在のルールで既存15方略を同一100seedで比較する。S+率だけでなく退塾、入退差40/48、動員40/50、満足25/35、配置数、デッキ枚数、トークンを確認する。
2. PRO専用の軽い取得評価式を作り、安定・ドローと並行配置・高満足・動員と入退差の複数プロフィールを比較する。配置先の競合、経理コスト、入塾上限、発想による追加取得と希釈、疲労、整理による圧縮を考慮する。
3. S+目標の配置・削除方略も複数作成する。取得だけの変更と、プレイ方略を含む変更を別々に測る。既存方略の過去結果は書き換えない。
4. 開発seedで試行・特徴除去・代表場面の選択肢別再試行を行う。別seedの検証でモデルを選ぶ。係数を凍結後、未使用seedで到達率・中央値・95%区間を確認する。
5. 全カードをターン・不足・デッキ状況ごとに検索できるローカルHTML/JSON/CSVを残す。同伴得点・到達率は相関であり、カードの因果効果として表示しない。人間の記録、アシスト表示有無、自動方略は別集計とする。
6. UI、再開・リフレッシュ・発想・モード除外、計算時間、既存FRESH推薦の回帰を検証し、結果と再実行手順を記録する。

## 現時点の注意

既存の配置方略にはCSVと異なる中間閾値の近似がある。新方略は公式表を参照し、旧方略を比較基準として保存する。S+は一つの数値だけでは決まらない。たとえば退塾0で、動員50・入退差40・満足25、動員50・入退差48・満足15、または動員40・入退差40・満足35で14点に達する。入塾数が体験数を超えない制約も満たす必要がある。

開発100seedでは旧15方略のS+率は0〜2%、最高中央値は11。過去のルールの分析とは測定条件が異なる。改善率・到達率の保証はせず、現在のルールとプレイ方略での限界を併記する。ローカルChromiumのスマートフォン画面での測定は、iPhone Safari実機の性能測定とは区別する。
