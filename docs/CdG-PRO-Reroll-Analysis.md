# PRO初期リセマラ研究：方法と再現性

2026-10-03。人向けの結果・判断例は [攻略レポート](CdG-PRO-Reroll-Guide.md)。前回の11,250完走とは別の追加研究で、作業ブランチは `codex/pro-strategy-research`。本体のカード・ルール・推薦・画面は変更していない。

## 仮説と固定条件

本研究は**15点狙いのカテゴリ**に属する。一発勝負は最初の候補からリセットなしで1ゲームを完走するため、初期リセマラの成績を一発勝負へ適用しない。受け入れ後の中央値・下位分位は15点狙いの補助指標として保存する。ゲーム内の研修リフレッシュは通常ルールとして両カテゴリで利用できる。

初期2枚の取得は、ゲームを新規開始し直すことで選別できる。これを後続の取得と独立した開始条件として扱い、「受け入れたゲームの中央値・15点率」と「受け入れるまでのリセット数」を両方測る。

初回4候補から条件を満たすペアを選べれば受け入れる。満たさなければゲームをリセットし、基本5枚・研修プール・トークン・数値・ゲーム内リフレッシュ2回を新規開始の状態へ戻す。条件を満たした後は完走し、将来の手札・研修候補・結果で採否を変更しない。初回の研修リフレッシュは `public-engine` の基準だけで利用し、その他は温存する。第2ターン以降は全て同じ公開情報のS+リフレッシュ評価を使用。

後続の基準は前回の `full-engine` と同じ取得・配置・役割を保つ積極削除。配置は可視手札の合法順序を幅180・深さ最大16で探索する。未来のゲームは回さず、所有カードから固定2回の算術投影で成長を近似する。条件・コスト・効果・入塾上限・解決順・最終得点はブラウザ内の本体関数を使用。Node側は起動・記録・集計だけを担う。

リセットの採否は、公開した初期候補から `initialPairIndices` で一致するペアを探すだけ。受け入れ可能なペアが複数ある場合、その中を同じ取得式で評価する。判断関数へ将来の研修山札・手札順・seed・乱数状態を渡さない。seedは実験を再現する実際の抽選処理にだけ使う。

## 何を数えているか

実際の `result.score.displayScore >= 15` を主な成功指標とし、14点以上は副指標。偶数件の中央値は中央2値の平均、分位点はnearest-rank。成功率はWilson 95%区間、差は同じ開始seedの組を単位に2,000回の対ブートストラップで測る。区間は比較ごとのもので、多重比較の補正はしていない。

リセマラなしと厳選ペアでは、受け入れる実際のseed・後続の抽選が異なる。対比較が示すのは**開始選別方略全体**の効果で、同じ後続の候補列に初期2枚だけを差し替えた効果でも、各カードの普遍的な因果順位でもない。保存した `firstOfferHash` は、受け入れ前の最初の開始候補を使い、全対比較で不一致0を確認した。

成功0件は成功率0の証明ではなく、0/250のWilson上限は約1.51%。確認群で基準とadaptiveが同じ5件だけ成功したため、ブートストラップの差の区間は[0,0]になるが、真の方略差が0とは証明できない。

本体の実行は画面タップの再生ではなく、ブラウザ内から本体関数を呼ぶ自動操作。自動操作は発想追加研修でUIの `trainingSelectionMode` を切り替えず、抽選関数の乱数系列名が実画面と異なる。提示は同じカード名の重複を避けるプール関数を使い、seedはこの分析器内の再現用とする。同じseedを画面へ設定したタップ操作で同じ候補列になることや、人の成功率・操作時間は検証していない。

## 出現率と時間換算

本体 `drawTrainingCards` は異なるカード名を選ぶ。初回は12種から4種の495組である。各2コピーの24枚から単純に4枚を引く計算は使わない。特定ペアは45/495、13＋15/16/17のいずれかは109/495。重なるペアの提示を二重に数えない。

開始条件の出現率をq、受け入れたゲームの15点率をp、リセット時間／1完走時間をrとすると、独立した開始・固定方略・一定の1完走時間を仮定して、

- 成功までの平均完走数：`1/p`
- 平均リセット数：`(1/q - 1)/p`
- 平均開始数：`1/(q*p)`
- 平均時間の完走換算：`[1 + (1/q - 1)*r]/p`

成功率の区間を換算した回数の区間も保存する。時間は観測成功率の点推定と理論qを使った感度分析で、実測時間や最短攻略時間ではない。厳選と緩い条件の双方がリセットする比較では、双方のリセット項を含めて交差点を求める。今回の点推定の交差点はr≈0.11549。成功率の不確実性を反映した確定境界とは扱わない。

## 再実行

ステージは順番に実行する。各ステージの2ジョブは並列にブラウザを起動するが、ステージ間で同じローカルポートを使用するため同時起動しない。

```bash
node solver/pro-reroll-study.mjs development 250
node solver/pro-reroll-study.mjs validation 1000 public-engine,any-engine,pair-7-15,pair-13-17,relaxed-finance --configs solver/research-scenarios/pro-reroll-configs.json
node solver/pro-reroll-study.mjs confirmation 250 pair-13-17,pair-13-17-acq-median,pair-13-17-place-myopic,pair-13-17-delete-off,pair-13-17-delete-basic,pair-13-17-delete-adaptive --configs solver/research-scenarios/pro-reroll-configs.json
node solver/pro-reroll-metrics.mjs solver/local-runs/pro-reroll/development/manifest.json solver/local-evaluation/pro-reroll/development
node solver/pro-reroll-metrics.mjs solver/local-runs/pro-reroll/validation/manifest.json solver/local-evaluation/pro-reroll/validation
node solver/pro-reroll-metrics.mjs solver/local-runs/pro-reroll/confirmation/manifest.json solver/local-evaluation/pro-reroll/confirmation
node --test tests/unit/*.test.mjs
```

各250完走ずつ保存し、新規バッチは自動で可逆圧縮する。`--resume` はseed範囲・方略設定・完走数・分析操作コード版・本体・カード・ランク版が一致したバッチのみ再利用。validationの追加の「13＋17対緩い条件」「7＋15対13＋17」は保存済み集計に含まれる。取得推薦へ適用する重み変更や、ゲーム内の自動リセットは実装していない。
