# あひる先生・FRESH版の準備

2026-11-03。`codex/ahiru-fresh-advice` をPRO画面開発のd982a61から分けた。PROの全2,000開始の検証、削除改善の開発比較、PRO画面ブランチにはこの変更を入れない。PROを先、FRESHを次の順に実装するための数式と共通部品の準備であり、FRESHは本体の表示へまだ接続していない。

## 準備した処理

- 公開デッキの2回の固定式投影を `ahiruForecast.js`、不足/余剰/順調の判定を `ahiruStatusPolicy.js` へまとめた。PROは既存の重み、公式得点、経路、イベントの扱いを渡す。FRESHは別の重み、得点、経路を渡す。同じ25文字のセリフと回復札の検査を使い、難易度ごとの得点ルールを混ぜない。
- FRESHの得点は新たに再実装せず、評価専用のScoreManagerから計算する。評価専用ではハイスコアの移行・保存を実行しない。通常のScoreManagerは従来どおり移行する。
- FRESHは表示の体験S基準15と、総合Sに必要な最小数値を区別する。公式計算から、体験12/入塾12/満足15/経理15、体験13/入塾13/満足14/経理15、体験13/入塾13/満足15/経理14の3つの最小整数経路を得た。退塾1人を許容できる別経路も認める。
- S成立後は丸め前の公式精度スコアを参照し、体験/入塾を伸ばす方向を案内する。通常の精度上限とイベントの上限超過加点を区別する。No50の経理12設定を、経理15までの直接回復として数えない。最終会議は現在値だけを使う。

## 確認済みと未完了

PROの関連17検査は共通部品へ移した後も通過。FRESHの6検査では、保存への非アクセス、公式得点/イベントとの一致、整数のS境界の広い確認、回復札/余剰の扱い、最終会議、初回の部分選択、非公開情報を読まないことを確認した。既存を含む全189単体検査が通過した。

これは実ゲーム250開始以上の予測精度や実機の速度を確認した結果ではない。FRESH用の補正値はまだ作っていない。既存のFRESH取得アシストとは別の機能であり、取得アシストの検証成績を新しいセリフの性能として扱わない。

次は過去のFRESHの公開判断・削除直前の記録を全開始で抽出する。既存のvalidation-reach 500開始を開発材料、別のholdout-reach 1,000開始を独立診断とし、同じ開始を混ぜない。補正の計算と助言の評価はブラウザ内で行い、元開始250未満の時期は傾向を出さない。PROの確認を先に進め、共通表示へ接続した後に取得/削除/中断再開を実画面で検査する。
