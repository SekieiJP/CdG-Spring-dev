# あひる先生・FRESH版の実装と検証

作業ブランチは `codex/ahiru-fresh-advice`。PROの画面開発d982a61から分け、PROに続いてFRESHも本体へ接続した。PRO方略の研究用ブランチとは独立し、MASTER・公開ブランチは変更していない。全体目標の1,000開始での方略達成と15指針は未完了。

## 実装した動作

取得・削除の各場面で、公開パラメータ、所有カード、残り日程、トークンを参照する。初回2枚は全て選ばれてから反映し、発想の追加取得/辞退と会議の削除選択も更新する。最終会議は現在値だけを使う。カード、選択、乱数、保存記録は操作しない。

PROと共通の44pxの顔ボタンをパラメータ直下に置く。タップで改行なし25文字以内のセリフを同じ行へ開閉し、操作の上に重ねない。赤い汗顔、黄色の気づき顔、緑の笑顔を使う。データ待ちも表示行を確保し、候補カードが後から上下へ動かないようにした。待機中の文は「教室の様子を見ているよ」。新ゲームと再読み込みは閉じて始まる。

難易度ごとの補正を別に読み込み、遅れて届いた他難易度の応答を使わない。取得失敗やカード/得点表の版違い、観測したデッキ枚数の範囲外では、現在デッキだけの固定式へ戻す。ゲーム本体で反復シミュレーションは行わない。

## 得点と共通部品

公開デッキの固定2回の投影を `ahiruForecast.js`、不足/余剰/順調の判定を `ahiruStatusPolicy.js` へまとめた。PROとFRESHはそれぞれの重み、公式得点、S経路を渡す。回復札の確認と表示を共通にし、難易度の得点ルールを混ぜない。

FRESHの得点は再実装せず、保存の移行を行わない評価用ScoreManagerから計算する。通常のScoreManagerは従来どおり移行する。公式の丸め前精度とイベントの上限超過加点を参照する。FRESHのNo50の経理12設定を、経理15までの直接回復として数えない。

表示上の体験S基準15と総合Sに必要な最小値を区別する。公式計算から得る最小整数経路は、体験12/入塾12/満足15/経理15、体験13/入塾13/満足14/経理15、体験13/入塾13/満足15/経理14。退塾1人を許容できる経路も認める。余剰の役を減らす助言では、除いた後の固定投影でも必要な得点と回復手段を失わないか確認する。

## 開発500開始と別1,000開始

過去の取得reach/配置削除fresh_stableの開発500開始から取得4,000・削除2,000、別1,000開始から取得8,000・削除4,000の公開判断を抽出した。全開始を採用し、開始の重複は0。[抽出監査](../solver/research-results/ahiru-advice-20261103/fresh-extraction.json)。

取得は記録された公開観測を使い、削除は実取得/実削除による所有札の追跡、最後の効果解決の数値/トークン、日程の削除枠から再構成する。次の取得観測と最終数値/デッキを全件照合した。効果やゲームを再実行せず、私用の個体ID・実seed・乱数・結果を公開入力に含めない。

ブラウザ内で開発500開始の24群の補正を作り、別1,000開始の全判断で25,000回の助言を診断した。各最終値の公式得点と最終会議のS判定は1,000/1,000一致した。[補正作成](../solver/research-results/ahiru-advice-20261103/fresh-calibration-audit.json)、[独立診断](../solver/research-results/ahiru-advice-20261103/fresh-advice-validation.json)。

通常取得後の得点の平均絶対誤差は、第1ターンで補正なし9.5038→補正あり0.7995、第5ターン1.2280→0.9347。一方、第7ターン0.5143→0.5699、第8ターン0.3687→0.3928とわずかに悪化した。診断を見て係数は再調整していない。補正は暫定のまま保存した。

この固定方略のS以上は87.6%。新しい助言に従った成績ではない。第1ターン取得後に緑となった67.0%の中でもS未達は全体の8.5%あった。未取得の将来カード、実際の手札、配置判断により結果は変わる。分位値は共同の予測区間や個別成功の保証ではなく、表情別の結果差も助言の因果効果や人間の成功率を示さない。

## 画面と処理の検査

全194単体検査と、PRO/FRESH助言30件・既存取得アシスト/スマートフォン操作/PWA配信と中断再開66件、計96件の画面検査が通過した。難易度別の応答が入れ替わった場合や失敗時の分離、効果による回復判定、Sの整数境界、初回選択、削除、再開、発想、25文字、非公開情報の非参照を含む。既存の初期オン設定と5秒後の取得カード強調も確認した。

データ応答を意図的に遅らせても、候補カードの座標が応答前後で一致した。FRESHの公開32状態での計算時間は、デスクトップ/iPhone 12寸法/Android寸法の95パーセンタイルが0.8/0.7/0.8ms、最大はいずれも1.3msだった。状態・乱数の不変も確認した。

いずれもこのMac上のChromiumとタッチ/端末寸法のエミュレーション。Safari実機の動作/速度、ホーム画面からの実起動とは区別する。現在のMacはPlaywright WebKit非対応で、実機SafariとCIのWebKit実行は確認していない。PWA検査は配信する設定・アイコンなどの確認であり、実機のホーム画面起動までを示さない。
