# Codex Step Play Plan

## 目的
- PRO を 1 手ずつ確認しながら操作し、S ランク (`points >= 12`) を狙う。
- UI クリックではなく `window.game` を直接操作し、各局面で合法手と推奨手を確認できるようにする。

## 採用する叩き台
- ベース方針: `pro_compress`
- 目的関数:
  - まず `経理15` と `満足15` に到達して退塾を止める
  - 次に `公開模試` を中心に `入退差` を伸ばす
  - `振込用紙印刷`、`入塾手続きのご案内`、`締切間近の書類リマインド` で圧縮と安定化を行う

## 手動試行で重視する判断
1. 取得
- 序盤は `経理/満足` の穴埋め札を優先
- `公開模試` は経理が崩れない前提で強く評価
- `整理`、`発想` は圧縮と中核札探索に寄与するため加点

2. 配置
- ターンおすすめボーナスを必ず加味する
- そのターン終了時の `体験`, `入塾`, `満足`, `経理` を実値でシミュレーションして並べる
- 過剰満足は減点する

3. 削除
- 基本は N 優先
- 特に `質問対応の基本`, `生徒面談の基本`, `問合対応の基本`, `経理精算の基本` を候補上位に置く
- 圧縮コア札 (`公開模試`, `書類リマインド`, `振込用紙印刷`, `入塾手続きのご案内`) は保持

## 実装方針
- `solver/codex-step-player.mjs`
  - `start`: 新規試行開始
  - `state`: 現在局面の要約表示
  - `recommend`: 現在局面の候補評価表示
  - `auto-step`: 現在局面の最善 1 手を実行
  - `pick-training`, `place`, `confirm-action`, `delete`, `confirm-meeting`: 明示操作
- セッションは永続 Chromium プロファイルで維持する
- 各操作ログは `solver/codex-step-session.jsonl` に追記する
